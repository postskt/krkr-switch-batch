# 真机测试指引（P0 首版：krkr-ns NRO）

> 适用对象：拿到本项目产出的 `krkrsdl2.nro` 后，在真机 Switch 上做首次验证。
> 你只需按本文操作并把「§6 结果回填」发回开发会话。所有真机结论以你的回填为准，本侧不臆测。

---

## 1. 前提条件

| 项 | 要求 | 自查方法 |
|---|---|---|
| 系统 | 已破解（CFW），Atmosphère 环境（建议 1.x 较新版本） | 开机进入的是 Hekate/Atmosphère 引导 |
| 启动方式 | **title-takeover（完整内存模式）**：按住 R 键点一个已安装的实体/数字游戏进入 HBMenu | 见 §3；直接从相册（applet）进入内存不足，krkr-ns 会拒绝启动大游戏（代码内 ≥1GiB 门槛） |
| SD 卡 | exFAT/FAT32 均可；游戏路径**必须全 ASCII**（英文/数字/下划线），目录名和 .xp3 文件名都不得含中文 | krkr-ns 已知限制 |
| 测试游戏 | **仅使用你合法拥有正版的游戏**。本侧不分发任何游戏资源 | — |

不需要：签名补丁（sigpatches）、装 NSP、联网、DBI 等安装工具——NRO 只要从 HBMenu 加载即可。

## 2. SD 卡目录准备

```
sdmc:/switch/KRKR-ns/
├── krkrsdl2.nro            ← 本项目产出的 NRO
├── Game/
│   └── TestGame01/         ← 测试游戏目录（ASCII 名）
│       └── data.xp3        ← 游戏入口包（入口必须 .xp3）
└── （log/、saves/ 等由程序自动创建，无需手动建）
```

要点：
- 入口必须是 `.xp3` 文件——只有展开的 `startup.tjs`、没有 .xp3 的游戏暂时不能从游戏库启动（代码硬限制）。
- 同目录下的其他 `.xp3` 会作为资源包自动挂载。
- 不要重命名 XP3 内部资源；散装资源改名要同步检查脚本引用。

## 3. 启动操作（title-takeover）

1. 开机进入 CFW 后的主界面。
2. **按住 R 键**的同时，点开任意一个**已安装的游戏**（实体卡或数字版均可）。
3. 若配置正常，出现的不是游戏而是 Homebrew Menu（HBMenu）。
4. 在 HBMenu 里选中 `krkrsdl2.nro` 按 A。
5. 出现 krkr-ns 浅色游戏库界面 → 选中 TestGame01 → 按 A「开始游戏」。

> 如果按住 R 仍进了游戏而不是 HBMenu：检查 Atmosphère 的 `override_config.ini`（`title-takeover` 需要按 R 启动已安装游戏；该文件位于 `sdmc:/atmosphere/config_packages/override_config.ini` 或全局 `config_templates` 同名文件）。
> 若内存不足启动器会给出提示和重试入口——这通常说明你从相册（applet）进入了，重来第 2 步。

## 4. 测试用例（按序做，结果逐条记）

| # | 操作 | 预期现象 |
|---|---|---|
| T1 | 启动 NRO | 游戏库界面出现，手柄 A/B/翻页可用，触摸可点 |
| T2 | 选中游戏按 A | 加载进入游戏标题/开场（加载时间视游戏大小） |
| T3 | 推进对话若干分钟 | 文字/立绘/背景正常显示；B 键=右键菜单、A=推进 |
| T4 | 存档/读档（含快速存读：Minus=F5 快存、R3=F7 快读） | 存档可用，读档回到原位 |
| T5 | 打开游戏内系统菜单（Plus=Escape） | 菜单可操作，含确认弹窗则确认流程正常 |
| T6 | 游戏内选「结束游戏」/正常退出 | 返回游戏库界面（不报错、不黑屏死机） |
| T7 | 换第二个游戏再启动一次 | 游戏库切换正常，存档互不串 |
| T8 | （可选）若有 E-mote 立绘的游戏：重复 T2-T6 | 立绘动态效果正常或有轻微异常（记下现象，E-mote 部分特性是已知空实现） |
| T9 | （可选）若游戏带 xp3filter.tjs 解密脚本：随游戏目录放入该文件后启动 | 加密资源能正常读取 |

> T8/T9 不强求——P0 只需 T1-T7 的基线结论。遇到游戏崩溃/报错，记录现象+游戏名（版本），不要反复重试烧机。

## 5. 日志收集

1. **运行日志**：`sdmc:/switch/KRKR-ns/log/` 下，自动保留最近 3 份（`.log`/`.txt`）。每次测试后把整个 `log/` 目录拷到 PC（读卡器或 FTP/Sys-FTPD 均可）。
2. **崩溃现场**：若报「软件已关闭以避免错误」：记下出现时机（哪个测试用例、操作后几秒）+ 截图。
3. **回传内容**：`log/` 目录 + 截图 + §6 回填表。无需其他系统级转储。

## 7. 已知预期（不是 bug，不用当缺陷报）

- 游戏路径含中文 → 游戏扫描不到/启动失败（ASCII 硬限制）
- 散装 startup.tjs 无 .xp3 → 不能从游戏库启动
- 视频不支持片段循环/变速/多音轨；MKV/WebM 不在白名单
- 含名字输入等文本输入框的环节目前无法输入（软键盘未实现）——遇到请记录游戏名，作为 fallback 线测试用例

## 8. Kirikiroid2-NX 线（后续同表复用）

fallback 线测试时改动两处：NRO 放 `sdmc:/switch/`，游戏放 `sdmc:/kirikiri/<game>/`（安卓同款目录结构）；日志在 `sdmc:/switch/kirikiroid2/` 下的 `k2s_boot.txt` / `k2s_crash.txt`。已知预期增加两条：Yes/No 系统弹窗恒选第一项；退出游戏可能报「软件因错误关闭」。
